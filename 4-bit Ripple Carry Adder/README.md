# 4-Bit Ripple Carry Adder in Verilog

## Overview

This project implements and simulates a **4-bit Ripple Carry Adder (RCA)** using structural Verilog. The design is constructed by cascading four 1-bit Full Adder modules, where the carry output of each stage is connected to the carry input of the next stage.

The project demonstrates basic RTL design, hierarchical module instantiation, combinational logic, testbench development, simulation, and waveform analysis.

The design was simulated using **Icarus Verilog**, with **GTKWave** used to analyze the resulting signal waveforms.

## Design Architecture

A 4-bit Ripple Carry Adder performs binary addition of two 4-bit inputs:

- `x[3:0]` - First 4-bit input
- `y[3:0]` - Second 4-bit input
- `s[3:0]` - 4-bit sum output
- `co` - Final carry-out

The RCA consists of four cascaded Full Adders.

```text
             ┌─────────────┐
x[0] ───────►│ Full Adder  │────► s[0]
y[0] ───────►│     FA0     │
             └──────┬──────┘
                    │ w1
                    ▼
             ┌─────────────┐
x[1] ───────►│ Full Adder  │────► s[1]
y[1] ───────►│     FA1     │
             └──────┬──────┘
                    │ w2
                    ▼
             ┌─────────────┐
x[2] ───────►│ Full Adder  │────► s[2]
y[2] ───────►│     FA2     │
             └──────┬──────┘
                    │ w3
                    ▼
             ┌─────────────┐
x[3] ───────►│ Full Adder  │────► s[3]
y[3] ───────►│     FA3     │────► co
             └─────────────┘
```

The first Full Adder receives a fixed carry-in of `0`. Each subsequent Full Adder receives the carry generated by the preceding stage.

Therefore:

```text
FA0 carry-out → w1 → FA1 carry-in
FA1 carry-out → w2 → FA2 carry-in
FA2 carry-out → w3 → FA3 carry-in
FA3 carry-out → co
```

This sequential dependency of carry signals gives the circuit its name, Ripple Carry Adder.

## Full Adder Design

Each 1-bit Full Adder accepts three inputs:

- x
- y
- ci - Carry-in

and produces:

- s - Sum
- co - Carry-out

The Full Adder is implemented using basic XOR, AND, and OR gates.

Logic Equations
Sum       = x ⊕ y ⊕ ci

Carry-out = (x · y) + (ci · (x ⊕ y))

Four Full Adders are instantiated hierarchically to construct the 4-bit RCA.

## Testbench Verification

The testbench applies five input combinations to the RCA. Each test case is separated by a 10 ns simulation interval.

### Test Results

| Test Case | `x` | `y` | Expected Decimal Result | `s[3:0]` | `co` |
|-----------:|----:|----:|------------------------:|----------|------|
| 1 | 3 | 2 | 5 | `0101` | `0` |
| 2 | 5 | 4 | 9 | `1001` | `0` |
| 3 | 7 | 8 | 15 | `1111` | `0` |
| 4 | 15 | 1 | 16 | `0000` | `1` |
| 5 | 10 | 6 | 16 | `0000` | `1` |

The complete result is represented by combining the carry-out with the 4-bit sum:

```text
Total result = {co, s[3:0]}
```
For example:

### Test Case 4: 15 + 1 = 16

```text
  1111
+ 0001
------
1 0000
↑ ↑↑↑↑
co  s
```

Therefore:

```text
co = 1
s  = 0000
```

### Test Case 5: 10 + 6 = 16

```text
  1010
+ 0110
------
1 0000
```

giving:

```text
co = 1
s  = 0000
```

## GTKWave Simulation

The generated VCD file was loaded into GTKWave to analyze the behavior of the RCA over the complete 50 ns simulation.

The waveform includes:

- `x[3:0]` - First input
- `y[3:0]` - Second input
- `s[3:0]` - Sum
- `co` - Final carry-out
- `w1` - Carry from the first Full Adder
- `w2` - Carry from the second Full Adder
- `w3` - Carry from the third Full Adder

### Waveform Interpretation

Each 10 ns interval corresponds to one test case:

| Simulation Time | `x` | `y` | `s` | `co` | Result |
|-----------------|-----|-----|-----|------|--------|
| 0–10 ns | `3` | `2` | `5` | `0` | `3 + 2 = 5` |
| 10–20 ns | `5` | `4` | `9` | `0` | `5 + 4 = 9` |
| 20–30 ns | `7` | `8` | `F` | `0` | `7 + 8 = 15` |
| 30–40 ns | `F` | `1` | `0` | `1` | `15 + 1 = 16` |
| 40–50 ns | `A` | `6` | `0` | `1` | `10 + 6 = 16` |

GTKWave displays the 4-bit signals in hexadecimal by default. Therefore:

```text
A = 1010₂ = 10₁₀
F = 1111₂ = 15₁₀
```

The internal carry signals `w1`, `w2`, and `w3` allow the carry propagation between individual Full Adder stages to be observed.

## Carry Propagation

The `15 + 1` test case demonstrates carry propagation through the complete 4-bit adder:

```text
        w1       w2       w3       co
         │        │        │        │
         ▼        ▼        ▼        ▼
       ┌────┐   ┌────┐   ┌────┐   ┌────┐
       │ FA0│──►│ FA1│──►│ FA2│──►│ FA3│
       └────┘   └────┘   └────┘   └────┘
```

For:

```text
x = 1111
y = 0001
```

the carry generated at the least significant bit propagates through each subsequent Full Adder, producing:

```text
w1 = 1
w2 = 1
w3 = 1
co = 1
```

with the final result:

```text
s  = 0000
co = 1
```

Since no explicit gate delays were modeled in the RTL, the carry propagation appears to settle within the same simulation time step in GTKWave. Physical propagation delay would depend on the implementation technology and gate characteristics.
